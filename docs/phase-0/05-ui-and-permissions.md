# 05 — الواجهات العربية RTL ونموذج الصلاحيات

> تصميم أولي (Wireframes نصية). الأرقام في الأمثلة توضيحية كما في الصورة المرفقة، وليست بيانات النظام.

## 1. مبادئ التصميم
- `<html lang="ar" dir="rtl">`؛ استخدام **Logical Properties** (`margin-inline-start`) بدل left/right؛ الأيقونات الاتجاهية تنعكس.
- الخط: **Cairo** أو **Tajawal** (مستضاف محلياً ضمن التطبيق للعمل دون إنترنت).
- الأرقام: **أرقام لاتينية (0-9)** مع فواصل آلاف كما في الصورة، قابلة للتبديل لأرقام هندية في الإعدادات؛ الأرقام داخل النص العربي بـ `dir="ltr"` عبر `<bdi>`/`unicode-bidi: isolate` لمنع انقلابها.
- التاريخ: ميلادي افتراضياً (`dd/MM/yyyy`) مع خيار هجري للعرض فقط.
- الوضع الداكن/الفاتح (الصورة داكنة)، وتباين WCAG AA، وأهداف لمس ≥ 44px.
- **Mobile-first**: شريط تنقل سفلي (5 عناصر)، والقائمة الكاملة في درج جانبي من اليمين؛ جداول الكمبيوتر تتحول لبطاقات على الجوال.
- المستخدم لا يرى «قيوداً محاسبية» إلا في صفحة «المحاسبة» للمالك والمحاسب المخوّل.
- كل شاشة مالية: حالة المستند (مسودة/مراجعة/مرحّل/معكوس) بلون وأيقونة ونص؛ عدم الاعتماد على اللون وحده.
- شريط حالة دائم: 🟢 متصل / 🟠 بانتظار المزامنة (N) / 🔴 غير متصل / ⚠ تعارضات (N).

## 3. الشاشة الرئيسية (مطابقة للصورة المرفقة، مع تعريفات واضحة)

```
┌────────────────────────────────────────────────────────┐
│ لوحة التحكم المالية                              [IQD ▾]│
├───────────────────────────┬────────────────────────────┤
│ رأس المال                 │ رصيد الصندوق               │
│ 10,000,000                │ 3,250,000                  │
├───────────────────────────┼────────────────────────────┤
│ قيمة المخزون              │ ديون العملاء               │
│ 5,400,000  (رئيسي|عهدة)   │ 2,100,000  (مستحق منها ⚠)  │
├───────────────────────────┼────────────────────────────┤
│ ديون الموردين             │ صافي ربح الفترة (استحقاق)   │
│ 750,000                   │ 1,500,000                  │
├───────────────────────────┴────────────────────────────┤
│ الربح القابل للتوزيع: ‏X   ← مستقل عن صافي الربح        │
│ توزيع الأرباح      حصتك: 750,000 │ حصة الشريك: 750,000 │
└────────────────────────────────────────────────────────┘
```
تعديلات مقترحة على التصميم المرفق (بسبب التعارضات C-1, C-2):
1. تسمية صريحة لـ «صافي ربح الفترة (استحقاق)» وإضافة بطاقة «الربح القابل للتوزيع» المنفصلة.
2. بطاقة الصندوق تعرض الإجمالي + سطراً صغيراً «عهدة الشريك: …» ولا تدمجها في الرصيد.
3. شارة «⚠ فرق ميزانية» تظهر فقط إن اختلّت المعادلة المحاسبية (يجب ألا تظهر).
4. نقر البطاقة يفتح تقرير تفصيلي؛ مقارنة بالفترة السابقة (▲▼ %).
5. رسوم: خط للإيرادات/المصاريف الشهرية، أعمدة لأفضل الأصناف، دائري للمصاريف (ألوان ثابتة ومتباينة + أنماط/تسميات).

## 4. أمثلة شاشات تشغيلية

### 4.1 فاتورة بيع (موبايل)
```
‹ فاتورة بيع            [مسودة] ⏳بانتظار المزامنة
العميل  [ بحث/اختيار ▾ ]       التاريخ [ ]
العملة  [IQD ▾]  سعر الصرف [1,480] (يدوي)
── البنود ──
[كود/اسم] [الكمية][الوحدة▾][السعر] المتاح: 150 (FIFO)
… إضافة بند +
الخصم  [ ] الإجمالي: ──
نوع الدفع (نقدي/آجل) | قبض الآن: [ ] إلى: [الصندوق | عهدة الشريك]
شروط/ملاحظات | مرفقات
[حفظ مسودة]    [ترحيل] ← يتطلب اتصالاً + صلاحية اعتماد
```
- الأوفلاين: يختفي زر «ترحيل» ويحل محله «إرسال للمزامنة»؛ لا يظهر رقم نهائي.
- بعد الترحيل: «رقم المستند»، «طباعة PDF»، «مستند عكسي».

### 4.2 تسوية الأرباح (المالك)
```
الفترة [01/11 – 30/11]     [احتساب]
أرباح مؤهلة للتحصيل (E)        +
مصاريف مستحقة (X)              −   (منها رواتب مستحقة)
تسويات سابقة (A)               ±
خسارة مرحّلة (L)               −   مُطبّقة / متبقية
محجوز (R) [ إدخال + سبب ]      −
══════════════════════════════
الربح القابل للتوزيع (D)       =
المالك 50% | الشريك 50%  | السيولة المتاحة بعد الالتزامات: …
[تفاصيل الفواتير] [اعتماد التسوية (المالك)] [تسجيل دفعة]
```
- تحذيرات حمراء إن تجاوز مبلغ الدفعة السيولة أو الحصة المتبقية.
- لا يوجد زر «إعادة توزيع»؛ التكرار يُرفض برسالة واضحة.

### 4.3 المخزون
جدول: الصنف، المتاح في الرئيسي، المتاح عند الشريك، التكلفة (FIFO)، القيمة، آخر حركة؛ وتبويب «الطبقات» لكل صنف (تاريخ الاستلام، الكمية المتبقية، تكلفة الوحدة، المصدر).

### 4.4 الحزمة المطبوعة (A4 عربي)
ترويسة: شعار + اسم الشركة + عناوين/هواتف؛ يمين: رقم/تاريخ؛ جدول البنود؛ الإجماليات؛ الشروط؛ التوقيع؛ تذييل رقم الصفحة؛ باركود/QR للتحقق (اختياري). المستندات: فاتورة، عرض سعر، سند قبض/صرف/تحويل/تسليم، كشف عميل/مورد/شريك.

## 5. نموذج الصلاحيات (RBAC على الخادم)

### 5.1 المبادئ
- صلاحية = (مورد × إجراء) من: `view / create / edit_draft / approve / cancel / print / export`.
- الأدوار قوالب ابتدائية؛ المالك يعدّل صلاحيات المحاسب من «الإعدادات ← المستخدمون».
- **كل نداء API يفحص الصلاحية على الخادم** (middleware + اختبارات تكامل لكل مسار).
- `owner_only = true` لا يمكن منحه لأي مستخدم غير المالك (حتى بتعديل DB عبر الواجهة).
- المحاسب لا يمنح نفسه (CHECK في DB) ولا يعدّل صلاحياته.
- الفصل بين المُدخِل والمُعتمِد: إعداد لكل مورد؛ إجباري لرأس المال والتسويات.

### 5.3 سير موافقة سحب رأس المال
```
المحاسب: ينشئ طلب سحب [REQUESTED] + سبب + مرفق
 → إشعار للمالك
المالك: يراجع الرصيد النقدي (والالتزامات) → يعتمد [APPROVED] (2FA)
 → النظام يرحّل القيد (3100 مدين / الصندوق دائن) [POSTED] ويسجل audit
أي محاولة اعتماد من غير المالك ⇒ 403 + سجل محاولة
```

### 5.4 فحوص الأمان الإضافية
- إعادة إدخال كلمة المرور/2FA للعمليات الحرجة (رأس المال، تسوية الأرباح، الاستعادة).
- جلسة منفصلة لكل جهاز؛ المالك يرى الأجهزة ويلغيها.
- تحديد معدل: دخول 5 محاولات/دقيقة/IP، API عام 100 طلب/دقيقة/مستخدم (قابل للضبط).
