## 1. الحالات الإلزامية (SRS §11) مع النتائج المتوقعة المحسوبة

| TC | السيناريو | النتيجة المتوقعة (قيود/أرقام) | الحالة |
|---|---|---|---|
| **TC-01** | رأس مال 10,000,000؛ شراء 100×10,000 ثم 100×12,000؛ بيع 150 | قيد الإيداع: مدين الصندوق / دائن 3100 = 10,000,000. COGS = 100×10,000 + 50×12,000 = **1,600,000**؛ المتبقي 50×12,000 = **600,000**؛ رصيد سالب مرفوض | ✅ (J-1, F-1..F-4) ثم ⏳2 على المحرك الحقيقي |

## 2. اختبارات إضافية لكل ثابت محاسبي

| المجال | الاختبار | الحالة |
|---|---|---|
| الدفتر | كل مستند مرحّل ⇒ قيد متوازن؛ مجموع ميزان المراجعة = 0 بعد أي سيناريو (Property-based) | ✅ جزئياً (J-*) ⏳4 |
| الدفتر | عكس مستند ⇒ قيد معاكس بنفس الحسابات والأسعار الأصلية؛ ميزان المراجعة يعود لما قبل | ⏳3 |
| المخزون | توازن: Σ مخزون الطبقات = رصيد 1300+1310 في الدفتر (Reconciliation دائم) | ⏳2 |
| المخزون | تزامن: 20 طلب بيع متوازٍ على 10 وحدات ⇒ المباع ≤ 10 بلا deadlock دائم | ⏳2 |
| المخزون | عكس فاتورة بيع ⇒ الطبقات نفسها تستعيد الكميات | ⏳3 |
| المخزون | عكس فاتورة شراء استُهلكت ⇒ مرفوض | ⏳2 |
| الوحدات | كارتون بعامل 12 لصنف و24 لآخر؛ كسور؛ عدم افتراض ثابت | ⏳2 |
| العملة | ربح/خسارة صرف محققة فقط؛ تقريب IQD/USD؛ حفظ السعر الأصلي بعد الترحيل | ⏳1/3 |
| التحصيل | تخصيص قبض على فواتير متعددة؛ قبض زائد ⇒ رصيد دائن 2400؛ استرداد | ⏳3 |
| الربح | المرتبط بالتحصيل ≤ 100%؛ فاتورة صافيها صفر؛ مرتجع كامل؛ قبض بعد مرتجع | ⏳3/4 |
| الأرباح | مرتجع بعد تسوية معتمدة ⇒ تسوية سالبة في الفترة التالية دون تعديل رجعي | ⏳4 |
| الأرباح | رفض الدفع إن تجاوز **الصندوق الرئيسي** (دون العهدة) − الالتزامات المقررة | ⏳4 |
| الرواتب | شهران متتاليان؛ دفع جزئي؛ دفع زائد مرفوض | ⏳4 |
| الافتتاحي | ميزانية افتتاحية غير متوازنة ⇒ رفض + عرض الفرق؛ لا قيد 3900 تلقائي | ⏳4 |
| الإقفال | ترحيل في فترة مغلقة ⇒ رفض؛ إعادة فتح بموافقة المالك مع سجل | ⏳4 |
| الترقيم | ترحيل متوازٍ ⇒ لا تكرار ولا فجوات؛ Rollback لا يستهلك رقماً | ⏳1 |
| التدقيق | كل ترحيل/إلغاء/تعديل يخلّف سجلاً؛ لا تعديل لـ audit_logs | ✅ (immutable) + ⏳1 |
| الأمن | SQLi، XSS في أسماء/ملاحظات، CSRF، IDOR (مستند شركة أخرى)، رفع ملف ضار، تجاوز rate limit، تثبيت الجلسة | ⏳1/6 |
| RLS | دور التطبيق بلا `BYPASSRLS` لا يقرأ شركة أخرى | ⏳1 |
| PWA | تثبيت، offline shell، إعادة إرسال، انقطاع أثناء المزامنة، مسح البيانات عند الخروج | ⏳5 |
| RTL/طباعة | لقطات بصرية لـ A4 (PDF) عربية: ترقيم، تشكيل، اتجاه الجداول، أرقام | ⏳5 |
| Excel | الأعمدة والأرصدة تطابق التقرير على الشاشة (مقارنة آلية) | ⏳5 |
| الأداء | ترحيل فاتورة 50 سطراً < 1 ث؛ لوحة التحكم < 2 ث على 100 ألف سطر قيد (أهداف مقترحة تُقاس في 6) | ⏳6 |
| النسخ | كل نسخة مشفرة وقابلة للفك بمفتاح المالك؛ فشل النسخ يرسل تنبيهاً | ⏳6 |

## 3. معايير القبول لكل مرحلة (Definition of Done)

**شروط عامة لكل مرحلة**: الكود + الاختبارات (وحدة/تكامل) + migrations + طريقة التشغيل والتراجع + تقرير المنجز/المتبقي + CI أخضر + لا أسرار في المستودع + **موافقة المالك الصريحة قبل المرحلة التالية**.

| المرحلة | معيار القبول |
|---|---|
| **0** | وثائق ADR/ERD/القيود/PWA/الواجهات/الاختبارات؛ المخطط يعمل على PostgreSQL 16 و29 اختباراً ناجحاً؛ قرارات D-01..D-16 مجابة |
| **1 Foundation** | `docker compose up` يشغّل التطبيق وDB؛ دخول Argon2id + جلسات؛ RBAC على الخادم مع اختبار لكل مسار؛ المحاسب لا يمنح نفسه؛ عملات وسعر صرف يدوي؛ audit_logs؛ RLS؛ واجهة RTL أساسية؛ CI يشغّل migrations والاختبارات |
| **2 Products/Purchases/Inventory** | TC-01, TC-02, TC-07b؛ اختبار تزامن؛ توازن الدفتر مع المخزون = 0 |
| **3 Sales/Receivables** | TC-03 (جزء), TC-07a, TC-07c؛ المستندات العكسية؛ كشوف العملاء والموردين وأعمار الديون |
| **4 Finance/Partners** | TC-03..TC-08c؛ ميزان مراجعة متوازن؛ إغلاق فترة؛ منع التوزيع المكرر؛ الافتتاحي |
| **5 Reports/PWA** | لوحة التحكم تطابق الدفتر؛ PDF/Excel؛ TC-09؛ اختبارات offline على متصفح حقيقي؛ RTL |
| **6 Hardening** | E2E + أمن + أداء + TC-11؛ Runbook؛ نشر تجريبي ثم إنتاجي **بعد قبول المالك**؛ النسخ المشفر خارج الخادم يعمل |

## 4. بوابات CI المقترحة
1. lint + typecheck + **قاعدة تمنع float للمال**.
2. تشغيل migrations على قاعدة نظيفة + `ledger_invariants.sql`.
3. فحص آلي: لا `ON DELETE CASCADE` ولا `FLOAT/REAL/DOUBLE` في أي migration مالية.
4. اختبارات الوحدة (domain) + التكامل (DB حقيقية بحاوية).
5. فحص الأسرار (secret scanning) + تدقيق الاعتماديات.
6. بناء صورة Docker + فحص ثغرات (Trivy).
