## 2. قواعد عامة للقيد

1. كل قيد: `Σ مدين = Σ دائن` بالعملة الأساس IQD (ويُحفظ المبلغ الأصلي وعملته وسعره في كل سطر).
2. قاعدة سعر الصرف: **IQD لكل 1 USD**، `amount_base = ROUND(amount_original × fx_rate, 0)` للـ IQD.
3. السعر مثبت في المستند (`exchange_rate_snapshot`) ولا يتغير بعد الترحيل.
4. التقريب: عند السطر، وفرق التقريب الإجمالي (≤ 1 وحدة) يُضاف لسطر التقريب في نفس المستند (مصروف/دخل تقريب 7100) — لا يُترك القيد غير متوازن.
5. الرقم النهائي للمستند يصدر عند الترحيل فقط.
6. التصحيح: مستند عكسي يُنشئ قيداً معاكساً بنفس الحسابات وبالأسعار الأصلية، ويُعيد طبقات FIFO التي استهلكها المستند الأصلي.

## 4. FIFO — الخوارزمية

### 4.1 البيانات
`stock_lots(id, product_id, location_id, source_lot_id, received_at, qty_received, qty_remaining, unit_cost_base, fx_rate_snapshot, unit_cost_orig, currency)` — الكمية بالوحدة الأساسية.

### 4.2 الاستهلاك (بيع/تسليم/نقل/نقص جرد)
```
BEGIN
  تحويل الكمية المطلوبة إلى الوحدة الأساسية
  لكل (product, location) بترتيب ثابت:
    SELECT lots WHERE qty_remaining > 0
      ORDER BY received_at ASC, id ASC FOR UPDATE
    إن Σ qty_remaining < المطلوب  ⇒ ROLLBACK + خطأ INSUFFICIENT_STOCK
    استهلك من الأقدم فالأحدث:
       take = MIN(lot.qty_remaining, remaining_needed)
       INSERT stock_lot_consumptions(doc_line, lot, take, lot.unit_cost_base)
       UPDATE lot.qty_remaining -= take
  COGS = Σ take × unit_cost_base   (يُقرَّب مرة واحدة عند مجموع السطر)
COMMIT
```
### 4.3 النقل بين المواقع
لكل جزء مستهلك من طبقة مصدر → إنشاء طبقة جديدة في الموقع الهدف بنفس `unit_cost_base` و`fx_rate_snapshot` ونفس `received_at` وربطها بـ `source_lot_id`. **لا إيراد، لا COGS، لا تضيع الطبقات.**

### 4.4 مرتجع العميل
- إن ارتبط سطر المرتجع بسطر البيع الأصلي: تُعاد الكمية إلى **الطبقات التي استُهلكت** (حسب سجل الاستهلاك) بنفس التكلفة، ويُعكس COGS بنفس الأرقام.
- إن تعذّر التحديد (بيع قديم/مجمع): تُنشأ طبقة جديدة بتكلفة **متوسط تكلفة البيع** لذلك الصنف في الفاتورة الأصلية، ويُسجَّل استثناء موثق.

### 4.5 مرتجع المورد
المتاح = `qty_remaining` للطبقة الأصلية (وطبقات النقل المتفرعة منها في الموقع المختار). الكمية المباعة منها **لا تُرجع** إلا بتسوية استثنائية موثقة بموافقة المالك: يُقيَّد الفرق بين قيمة الاسترداد والتكلفة المستهلكة في 5200.

### 4.6 عكس المستند
إعادة `qty_remaining` من `stock_lot_consumptions` إلى الطبقات نفسها؛ يُمنع إن كانت الطبقة المعنية قد استُهلكت لاحقاً من مستند غير معكوس.

### 4.7 مثال إلزامي TC-01
شراء 100×10,000 ثم 100×12,000، بيع 150:
- COGS = 100×10,000 + 50×12,000 = **1,600,000**
- المتبقي = 50×12,000 = **600,000** ✔

## 5. وحدات القياس
- `product_uoms(product_id, uom, factor_to_base NUMERIC(20,6))` لكل صنف على حدة؛ الكارتون ≠ ثابت.
- الوحدة الأساسية دقيقة: عدد منازل الكمية قابل للضبط للصنف (0 للقطع).
- كل كمية تُحوَّل للأساس قبل المعالجة؛ يُحفظ سطر المستند بالوحدة الأصلية + الكمية الأساس.
- منع الكسر الذي يُنتج كمية أساس غير صحيحة حسب دقة الصنف.

## 6. العملات وفروقات الصرف
- كل مستند: `currency`, `exchange_rate_snapshot`, والمبلغ الأصلي والأساس.
- فرق صرف التسوية محقق فقط: `fx_diff = amount_USD × (rate_settlement − rate_invoice)` ← 7100 (ربح للعميل/خسارة حسب الإشارة).
- عدم إعادة تقييم الأرصدة الدفترية بالدولار في نهاية الفترة (غير محقق) — خارج SRS، ويُسجَّل كتحسين مستقبلي يحتاج قرار.
- المخزون المشترى بالدولار يحفظ `fx_rate_snapshot` في الطبقة؛ تكلفته الأساس ثابتة.

## 7. التحصيل الجزئي والتخصيص

1. كل `customer_receipt` يُوزَّع على فاتورة أو أكثر (`receipt_allocations`)، والمتبقي غير المخصص ← رصيد دائن 2400.
2. `net_collected_i = Σ allocations − refunds` للفاتورة i.
3. ربح الفاتورة المعدّل: `adj_profit_i = (net_sales_i − returns_i − discounts) − (COGS_i − returned_COGS_i)`.
4. **الربح المرتبط بالتحصيل** (مؤشر تقييدي):
```
linked_i = adj_profit_i × MIN(1, MAX(0, net_collected_i / adj_net_value_i))      إذا adj_net_value_i > 0
linked_i = 0                                                                      إذا adj_net_value_i ≤ 0
```
مثال TC-03: 300,000 × (500,000 / 1,000,000) = **150,000** ✔.

مثال مرتجع بعد تحصيل جزئي (TC-07a): فاتورة 1,000,000 تكلفتها 700,000؛ تحصيل 400,000؛ مرتجع 300,000 بتكلفة 210,000.
`adj_net = 700,000`، `adj_profit = 490,000`، `ratio = 400/700 = 57.142857%`، `linked = 280,000`.

## 8. تسوية الأرباح والتوزيع 50/50 (Profit Settlement)

### 8.1 المبدأ
تسوية = لقطة معتمدة لفترة تحدد مبلغاً قابلاً للتوزيع، ثم دفعات (جزئية) من هذا المبلغ فقط.

### 8.2 الجداول المؤثرة
`profit_release_ledger(source_type, source_id, settlement_id, amount)` — كل ربح فاتورة وكل مصروف يُستهلك مرة واحدة فقط بقيد تفرد وبحدّ تراكمي: `Σ amount ≤ linked_i` (يفرضه trigger).

### 8.3 الخطوات (خوارزمية)
```
المدخلات: فترة P، X0 = مصاريف مستحقة غير مخصومة سابقاً، L = خسارة مرحّلة، R = محجوز يحدده المالك
1. لكل فاتورة i (مرحّلة، فيها تحصيل أو تعديل):
     newly_i = linked_i − released_i         (قد تكون سالبة بسبب مرتجع/استرداد)
2. E  = Σ newly_i                          // أرباح مؤهلة جديدة
3. X  = مصاريف الفترة المستحقة (6xxx) التي لم تُحمَّل بتسوية سابقة      // الراتب المستحق يُحسب ولو لم يُدفع
4. A  = تسويات تصحيحية معتمدة معلقة (سالبة غالباً)
5. B  = E − X + A                          // نتيجة الفترة بعد المصاريف
6. إن B < 0:  L' = L + |B| ؛  D = 0
   وإلا:       cover = MIN(L, B)؛  L' = L − cover
               D0 = B − cover − R
               D  = MAX(D0, 0)
7. قيد السيولة: عند الدفع فقط
     مدفوع ≤ الصندوق الرئيسي المتاح − الالتزامات المقررة (C-10)
8. التوزيع: partner_share = ROUNDDOWN(D / 2)، owner_share = D − partner_share
9. اعتماد (المالك فقط) ⇒ يقفل الأسطر في profit_release_ledger ويُنشئ القيد 3.7
```
**منع التكرار**:
- قيد تفرد على (source_type, source_id, settlement_id) وحدّ تراكمي على المصدر.
- `profit_payouts` بـ `idempotency_key` فريد، و`Σ payouts ≤ settlement_share` لكل شريك (trigger).
- إعادة إرسال نفس التوزيع ⇒ `409 DUPLICATE_PAYOUT` (TC-10).

### 8.4 ملاحظات تنبيهية
- **التمييز**: «خسارة التسوية المرحّلة» مفهوم تشغيلي لتقييد التوزيع، وليس خسارة محاسبية بالضرورة: فقد يكون الربح المحاسبي موجباً لكنه غير محصَّل بعد بينما المصاريف تُخصم كاملة، فتنشأ خسارة تسوية مرحّلة تُغطى لاحقاً عند التحصيل. أعرضها بوضوح باسم «خسارة مرحّلة للتسوية».
- لا ذمة على الشريك مقابل الخسارة (D-02).
- مرتجع/استرداد بعد التسوية ⇒ يظهر `newly_i` سالباً في التسوية التالية (D-08).

### 8.5 مثال عددي (توضيحي — ليس بيانات النظام)
E = 2,000,000؛ X = 700,000 (منها راتب مستحق 400,000)؛ A = 0؛ L = 300,000؛ R = 0
B = 1,300,000 ← cover = 300,000 ← D = 1,000,000 ← الشريك 500,000 / المالك 500,000.
إعادة إرسال التسوية نفسها أو الدفعة نفسها ⇒ مرفوضة.

## 10. الأرصدة الافتتاحية
مدخلات: رأس المال، النقد (بحسب الحساب)، المخزون بطبقات (صنف، موقع، كمية، تكلفة، تاريخ)، العملاء، الموردين.
```
Σ أصول (نقد + مخزون + عملاء) − Σ التزامات (موردون) = Σ حقوق (رأس المال + أرباح محتجزة افتتاحية صريحة)
```
- الفرق ≠ 0 ⇒ **يُرفض الاعتماد** ويُعرض الفرق؛ لا يُنشأ قيد 3900 تلقائي.
- الأرباح المحتجزة الافتتاحية لا تُقبل إلا بإدخال صريح موثق من المالك.
- أرصدة العملاء/الموردين الافتتاحية تُنشأ كمستندات افتتاحية قابلة للتخصيص والتحصيل.

```
                 ↘ REJECTED ↗ (يعود DRAFT)
DRAFT → DELETED (مسموح فقط للمسودة)   |  POSTED → لا تعديل ولا حذف
```
- الانتقال إلى POSTED: تحقق صلاحية + فصل المُدخِل/المُعتمِد (إن فعّله المالك) + فترة مفتوحة + الأرصدة (مخزون، نقد).
- العكس يتطلب سبباً وصلاحية `cancel`، وينشئ مستنداً جديداً مرتبطاً.
