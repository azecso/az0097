# 06 — PWA والعمل دون إنترنت والمزامنة

## 1. القرار (ADR-008 / D-12)
**الأوفلاين = مسودات فقط.** لا رقم مستند نهائي، لا ترحيل، لا خصم FIFO، لا تحقق رصيد نقدي نهائي إلا عند الخادم. الخادم هو المرجع الوحيد للحقيقة المالية.

## 2. ما يعمل دون اتصال

| الوظيفة | أوفلاين | ملاحظة |
|---|---|---|
| تصفح واجهة التطبيق | ✔ | Service Worker + Precache |
| قراءة بيانات مرجعية محدودة (عملاء، أصناف، أسعار، آخر سعر صرف) | ✔ قراءة فقط | نسخة مخبأة بتاريخ آخر مزامنة ظاهر |
| إنشاء مسودة عرض سعر | ✔ | |
| إنشاء مسودة فاتورة بيع | ✔ | بحالة «بانتظار المزامنة»؛ الرصيد المعروض **تقديري** |
| مسودة سند قبض | ✔ | |
| مسودة سند صرف/مصروف | ✔ | حسب السياسة؛ الصلاحية تُتحقق عند المزامنة |
| ترحيل/اعتماد/إلغاء | ✖ | يتطلب الخادم |
| رأس المال، تسوية الأرباح، الاستعادة، إدارة المستخدمين | ✖ | لا تُفتح أوفلاين إطلاقاً |
| تقارير ثقيلة/Excel/PDF نهائي | ✖ | PDF مسودة محلي بعلامة «غير نهائي» (اختياري) |
| الأرصدة الافتتاحية | ✖ | |

## 3. التخزين المحلي
- **Cache Storage**: ملفات الواجهة (hashed)، الخطوط، الأيقونات.
- **IndexedDB** (عبر Dexie): جداول `ref_customers`, `ref_products`, `ref_prices`, `ref_fx`, `drafts`, `outbox`, `meta`.
- **التشفير**: تشفير حقول المسودات بـ **AES-GCM عبر Web Crypto**؛ المفتاح مشتق (PBKDF2/Argon2-wasm) من قفل PIN/كلمة مرور المستخدم ولا يُخزَّن بالنص الصريح. يُحدّ الحماية بما يتيحه المتصفح (لا تحمي من جهاز مخترق)، فتبقى مبدأً: **أقل بيانات ممكنة**.
- لا تُخزَّن: كلمات المرور، رموز الجلسة غير HttpOnly، أرصدة الصندوق، بيانات رأس المال، الأرباح، سجل التدقيق.
- مسح تلقائي عند تسجيل الخروج، وبعد N أيام من عدم المزامنة، وزر «مسح البيانات المحلية» الإداري.
- الجلسة: الكوكي HttpOnly فقط؛ في وضع أوفلاين يُسمح بالقراءة/المسودات عبر «قفل محلي» (PIN) خلال فترة سماح قابلة للضبط (افتراضي 7 أيام) ثم يُطلب اتصال.

## 4. مخطط الـ Outbox
كل تغيير محلي = عملية في `outbox`، ثم تُرسل للخادم عند عودة الاتصال بالترتيب:

```json
{
  "operation_id": "uuid-v4 (يولده الجهاز)",
  "idempotency_key": "device_id:entity_local_id:seq",
  "device_id": "…",
  "entity_type": "sales_invoice | sales_quote | customer_receipt | expense",
  "entity_local_id": "uuid",
  "op": "CREATE_DRAFT | UPDATE_DRAFT | SUBMIT_FOR_POSTING",
  "base_version": 3,                    // نسخة الخادم التي بُني عليها التعديل (null للإنشاء)
  "payload": { … },
  "client_created_at": "ISO-8601"
}
```
يقابله جدول `sync_operations` (انظر `schema.sql`) بقيود `UNIQUE(operation_id)` و`UNIQUE(idempotency_key)` ⇒ إعادة الإرسال آمنة (اختبار S-1).

## 5. بروتوكول الخادم

`POST /api/sync/push` (دفعة مرتبة) → لكل عملية داخل معاملة مستقلة:

```
1. إن وُجد operation_id سابقاً ⇒ أعد نتيجته المخزنة (idempotent) دون تنفيذ
2. تحقق الجلسة + الصلاحية الحالية (قد تغيّرت منذ كتابة المسودة) ⇒ PERMISSION_CHANGED
3. تحقق الفترة المحاسبية مفتوحة ⇒ PERIOD_CLOSED
4. CREATE_DRAFT: تحقق الحقول؛ احفظ مسودة بإصدار 1  ⇒ ACCEPTED {server_id, version}
5. UPDATE_DRAFT: إن base_version ≠ version الحالي ⇒ CONFLICT(VERSION_MISMATCH) مع snapshot
6. SUBMIT_FOR_POSTING (اختياري حسب الصلاحية والسياسة):
      معاملة واحدة: قفل FIFO (SELECT … FOR UPDATE) → تحقق المخزون/النقد
        ⇒ كفاية ⇒ ترقيم نهائي + قيد + ترحيل ⇒ ACCEPTED {doc_no}
        ⇒ نقص   ⇒ ROLLBACK + CONFLICT(INSUFFICIENT_STOCK) {available}
7. سجّل النتيجة في sync_operations (+ sync_conflicts عند التعارض)
```
**الحالات الصريحة للعميل**: `ACCEPTED | REJECTED(سبب) | CONFLICT(نوع + snapshot)`.

## 6. معالجة التعارض (لا «آخر تعديل يفوز» في الحسابات)

| التعارض | المعالجة |
|---|---|
| تعديل مسودة نفسها من جهازين | `VERSION_MISMATCH` ⇒ شاشة مقارنة: «إبقاء نسخة الخادم / إنشاء مسودة جديدة من تعديلي / تجاهل». لا دمج تلقائي للمبالغ. |
| بيعان أوفلاين لنفس الرصيد | الترحيل يتم **بالتسلسل** على الخادم؛ الأول يُرحَّل، والثاني `CONFLICT(INSUFFICIENT_STOCK)` وتبقى مسودته معلقة. المخزون لا يصبح سالباً. |
| صرف أوفلاين يتجاوز النقد | `CONFLICT(INSUFFICIENT_CASH)` عند الترحيل |
| تغيّرت الصلاحية/أُغلقت الفترة | `REJECTED` مع سبب واضح |
| عميل/صنف أُرشف | `REJECTED(REFERENCE_ARCHIVED)` |
| سعر الصرف اختلف عن المخبأ | الاحتفاظ بالسعر المدخل كمسودة، وطلب تأكيد السعر قبل الترحيل |

## 7. الـ Service Worker والتحديث
- استراتيجية: *Precache* للأصول، *Stale-While-Revalidate* للمراجع، *Network-only* لـ `/api/*` المالية (لا تُخزَّن استجاباتها).
- إدارة الإصدارات: نسخة SW مرتبطة بإصدار التطبيق؛ تحديث يُعرض للمستخدم «تحديث جديد — أعد التحميل» (لا تحديث وسط تعديل).
- **Background Sync** إن توفر (Chrome)، وإلا عند فتح التطبيق وحدث `online`. (iOS Safari: لا Background Sync ⇒ المزامنة عند الفتح؛ يُنبَّه المستخدم.)
- التثبيت: `manifest.webmanifest` (dir=rtl, lang=ar, أيقونات maskable، `display: standalone`).

## 8. واجهة الحالة
شريط علوي دائم: متصل/غير متصل، عدد العمليات المعلقة، آخر مزامنة، أخطاء. صفحة «المزامنة» تعرض كل عملية وحالتها وزر إعادة المحاولة/حل التعارض. **تنبيه عند وجود مسودات معلقة أكثر من 24 ساعة.**

## 9. خطة التنفيذ (Phase 5) واختباراتها
1. طبقة `outbox` + Dexie + تشفير الحقول.
2. `/api/sync/push|pull` مع idempotency + إصدارات.
3. شاشات المسودات + حالات القبول/الرفض/التعارض.
4. اختبارات: بيعان أوفلاين (TC-12)، إعادة إرسال نفس العملية، انقطاع أثناء الدفعة، تغيّر الصلاحية، انتهاء الجلسة، تغيّر سعر الصرف، اختبار Playwright بوضع offline حقيقي على Chromium (وجهازين = سياقين).

## 10. مخاطر معروفة
- حدود تخزين iOS وتنظيف IndexedDB بعد فترة خمول ⇒ المسودات غير المزامنة معرضة للفقد؛ **تحذير بارز + زر «تصدير المسودات»**.
- التشفير في المتصفح لا يحمي من برمجيات خبيثة على الجهاز نفسه.
